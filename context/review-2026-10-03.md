The main performance changes remove repeated work while keeping SQLite
authoritative. With 1,000 tasks and 100,000 intervals, 25 repeated snapshot
samples measured a median **25.010 ms before versus 0.0644 ms after**. The first
snapshot following a mutation still aggregates the database. The cache relies
on the existing, documented single-owner database contract and returns copies
that callers cannot use to modify cached state.

An 8 MiB note transfer, including its initial stat and 64 chunks, now loads and
hashes the document once instead of 65 times. Five-sample medians were
**498.853 ms before versus 7.866 ms after**; an independent repeat measured
604.547 ms versus 8.554 ms. These local measurements vary with system load.
Read snapshots retain at most 16 MiB of encoded content, with bounded release
history that prevents delayed requests from recreating released jobs. Both
performance issue records include reproducible temporary-data benchmarks.

The default suite grew from **65 to 102 tests**. SQLite coverage now includes
actual denied commits rather than only mocked failures, the 1,000-task and
100,000-interval boundaries, 8 MiB per-note and 16 MiB aggregate UTF-8 byte limits,
simultaneous conditional saves, cache invalidation, durable state after failed
pause/status/import/recovery, and crash recovery. Note tests cover an error
reported after a successful durable save, ensuring reconciliation reads the
database and an abort cannot falsely claim to undo that save. Wire tests also
prove that an existing read job retains its version while a new job sees a save.
